# REQUIREMENTS.md — 需求规格

约定：FR = 功能需求，NFR = 非功能需求。"必须"为 v1.0 验收硬性条件。

## FR-1 排序算法可视化

- FR-1.1 必须实现：冒泡、选择、插入、归并、快速、堆排序，共 6 种。
- FR-1.2 输入：随机数组 / 自定义数组 / 几乎有序 / 逆序 / 大量重复值；数组大小可调（4–60）。
- FR-1.3 可视化必须区分：当前比较元素、正在交换元素、已排序区域、pivot（快排）、merge 范围（归并）。
- FR-1.4 必须显示：比较次数、交换次数、运行步骤（当前步/总步数）、时间复杂度、空间复杂度。
- FR-1.5 自定义数组输入必须校验（仅整数，数量与取值范围受限，错误用中文提示）。

## FR-2 搜索算法可视化

- FR-2.1 必须实现线性查找与二分查找。
- FR-2.2 必须展示：当前检查元素、搜索区间（二分）、mid（二分）、找到结果的高亮。
- FR-2.3 二分查找要求数组升序；输入无序时必须给出中文校验错误并提供"一键排序"。
- FR-2.4 必须覆盖"未找到"情形并在动画中明确表达。

## FR-3 栈与队列

- FR-3.1 栈：Push / Pop / Peek；队列：Enqueue / Dequeue / Front。
- FR-3.2 必须可视化入/出方向的元素与 top/front/rear 指针。
- FR-3.3 空结构 Pop/Dequeue、满结构（容量上限 12）Push/Enqueue 必须给出明确提示步骤。

## FR-4 单链表

- FR-4.1 至少实现单链表：建表、遍历、按位置插入、按位置删除、按值搜索。
- FR-4.2 必须展示节点链与箭头，遍历时 curr 指针移动，插入/删除时受影响节点高亮。

## FR-5 树

- FR-5.1 必须实现 BST：Insert / Search / Delete（删除含叶子、单子、双子三种情形）。
- FR-5.2 必须实现遍历：Preorder / Inorder / Postorder / Level Order。
- FR-5.3 树布局必须自动计算（同层等深、中序位置决定横坐标），结构变化后重排。
- FR-5.4 遍历必须展示访问顺序输出序列。

## FR-6 图

- FR-6.1 支持创建/编辑：节点、边、有向/无向、权重（1–99）。
- FR-6.2 必须实现 BFS、DFS、Dijkstra（起点必选，Dijkstra 终点可选）。
- FR-6.3 必须可视化：visited、当前节点、frontier（队列/栈/待定集）、边状态、距离值、前驱。
- FR-6.4 交互约束：节点 ≤ 12、无重复边、无自环、删节点时级联删边；所有输入校验。

## FR-7 递归

- FR-7.1 必须实现阶乘、斐波那契（朴素递归）、汉诺塔。
- FR-7.2 必须实时展示调用栈（帧入栈/等待/返回+返回值）；汉诺塔同时展示三柱盘子移动。

## FR-8 回溯

- FR-8.1 必须实现 N 皇后（4 ≤ n ≤ 8）。
- FR-8.2 必须展示：当前放置尝试、冲突检测、回退、已找到的解列表。

## FR-9 动态规划

- FR-9.1 必须实现斐波那契 DP（一维表）与 0/1 背包（二维表）。
- FR-9.2 必须展示 DP 表逐格填充、当前格子与依赖格子。

## FR-10 播放器

- FR-10.1 必须支持：Play / Pause / Next / Previous / Restart / Speed(0.25x,0.5x,1x,2x,4x)。
- FR-10.2 必须显示当前步/总步数，时间轴可拖动（seek）。
- FR-10.3 算法与动画解耦：算法仅产出标准化步骤序列；速度、暂停、单步、回退不得影响算法逻辑与结果；任意操作后结果必须可重放。
- FR-10.4 键盘快捷键：空格=播放/暂停，←/→=上一步/下一步，R=重播。

## FR-11 教学模式

- FR-11.1 每个算法页必须展示：算法名称、用途、核心思想、动画、伪代码、时间复杂度、空间复杂度、稳定性（排序类）、当前执行步骤解释。
- FR-11.2 伪代码当前执行行必须高亮，解释须具体（如"正在比较 a[3] 与 a[4]，因为 5 > 3，交换"）。

## FR-12 比较模式

- FR-12.1 同一组数据最多选择 3 种排序算法同步播放。
- FR-12.2 必须展示每算法：Steps / Comparisons / Swaps / 时间复杂度（表格）。
- FR-12.3 逻辑正确优先，不追求复杂特效。

## FR-13 交互实验

- FR-13.1 自定义数组、随机生成、调整数组大小（全部类别通用部分见 FR-1.2）。
- FR-13.2 图：拖动节点、增删节点、增删边、设起点/终点、设权重。
- FR-13.3 所有输入必须校验并给出中文错误信息。

## NFR 非功能需求

- NFR-1 技术栈：React + TypeScript(strict) + Vite；状态管理从简（React 内置状态 + 可订阅引擎），避免过度设计。
- NFR-2 架构：算法为纯函数 Generator，仅产出 Step；与 UI 完全分离；核心层禁止 import React。
- NFR-3 渲染：SVG 为主；排序柱状图、树/图节点边、调用栈、DP 表均用 SVG/HTML 混合，可读性优先。
- NFR-4 测试：Vitest；算法正确性、步骤完整性、播放器行为、输入校验全部自动化；禁止为通过测试而降低标准。
- NFR-5 质量：ESLint 0 warning；tsc strict 0 error；vite build 成功。
- NFR-6 主题：Dark 默认 + Light 切换，CSS 变量实现，持久化到 localStorage。
- NFR-7 可访问性：控件有 aria-label、焦点可见、动画尊重 prefers-reduced-motion。
- NFR-8 响应式：≥ 1024px 三栏布局；窄屏降级为纵向堆叠。
- NFR-9 性能：数组规模 ≤ 60、图 ≤ 12 节点、DP 表 ≤ 8×32 时交互流畅；步骤预计算内存可控（上限保护）。
